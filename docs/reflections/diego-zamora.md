Reflexión individual — Diego Zamora González (0267601)
¿Cuál fue mi contribución principal?

Después de realizar todo el proyecto, considero que mi principal contribución fue ayudar a conectar la parte técnica con una decisión que tuviera sentido para McCain. El objetivo no era quedarnos únicamente con un modelo o con varias gráficas, sino entender cómo toda esa información podía servir para identificar ciudades con mayor oportunidad y planear mejor una posible inversión.

¿Qué decisión técnica tomé?

Una de las decisiones más importantes fue validar el modelo respetando el orden del tiempo y compararlo con una estimación sencilla. De esta forma pudimos comprobar que el uso de machine learning realmente aportaba algo, al reducir el error de 4.10 a 3.65 puntos, aproximadamente un 11%. Aunque no significa que ahora podamos predecir exactamente lo que sucederá, sí representa una mejora útil para tomar decisiones con mayor fundamento.

¿Qué problema enfrenté?

Uno de los retos más importantes fue trabajar con las diferentes versiones del DENUE, porque los archivos no siempre utilizaban las mismas columnas, nombres o clasificaciones. Incluso encontramos datos que parecían correctos en formato, pero que no tenían sentido al revisar su comportamiento. Esto me ayudó a entender que analizar información no consiste solamente en limpiar bases de datos o entrenar un modelo, sino también en cuestionar los resultados y conectarlos con una situación real. En el caso de McCain, existen retos para calcular con mayor precisión la demanda y decidir cómo distribuir los recursos entre diferentes ciudades. El modelo puede ayudar a organizar esas decisiones, pero todavía necesita combinarse con información interna, experiencia comercial y una revisión de los supuestos.

¿Qué aprendí de Git y GitHub?

También aprendí que Git y GitHub son importantes no solamente para guardar el código, sino para mantener un historial claro del proyecto, identificar qué cambió y recuperar versiones anteriores cuando algo no funciona.

¿Qué aprendí sobre trabajo colaborativo?

Trabajar en equipo me mostró que dividir las tareas no es suficiente; también es necesario comunicarnos, revisar lo que hace cada integrante y asegurarnos de que todas las partes cuenten la misma historia.

¿Qué parte mejoraría?

Si volviera a realizar el proyecto, mejoraría la documentación de los supuestos desde el principio y haría validaciones intermedias con mayor frecuencia. También intentaría incorporar datos reales de ventas, participación de mercado y consumo por ciudad, porque eso permitiría acercar mucho más el escenario a la situación de McCain.

¿Qué contribución de otro integrante fue importante?

La contribución de mi compañero fue importante para integrar y revisar los resultados, además de convertirlos en un entregable interactivo que permitiera explorar las ciudades y comprender mejor lo que estaba mostrando el análisis. Esa parte ayudó a que el trabajo no se quedara únicamente en el código.

Al final, el aprendizaje más importante fue entender que un modelo no reemplaza la decisión de una persona, pero sí puede ayudar a estructurarla, hacer visibles ciertos patrones y reducir parte de la incertidumbre cuando se utiliza con cuidado.
